## 4. データベース設計

### テーブル: users

| カラム名 | データ型 | 制約 | 説明 |
|---------|---------|------|------|
| id | SERIAL | PRIMARY KEY | ユーザーID（自動採番） |
| name | VARCHAR(100) | NOT NULL | ユーザー名 |
| email | VARCHAR(255) | UNIQUE, NOT NULL | メールアドレス |
| created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 作成日時 |
| updated_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 更新日時 |

### DDL

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- サンプルデータ
INSERT INTO users (name, email) VALUES
    ('山田太郎', 'yamada@example.com'),
    ('佐藤花子', 'sato@example.com');
```

## 5. API仕様

### ベースURL
```
http://localhost:8080
```

### エンドポイント一覧

#### 1. ヘルスチェック
- **エンドポイント**: `GET /api/health`
- **説明**: APIの稼働状態を確認
- **レスポンス**:
```json
{
  "status": "ok"
}
```

#### 2. ユーザー一覧取得
- **エンドポイント**: `GET /api/users`
- **説明**: 全ユーザーを取得
- **レスポンス**:
```json
[
  {
    "id": 1,
    "name": "山田太郎",
    "email": "yamada@example.com",
    "created_at": "2025-10-28T10:00:00Z",
    "updated_at": "2025-10-28T10:00:00Z"
  }
]
```

#### 3. ユーザー詳細取得
- **エンドポイント**: `GET /api/users/:id`
- **説明**: 指定IDのユーザーを取得
- **パスパラメータ**: `id` (integer)
- **レスポンス**:
```json
{
  "id": 1,
  "name": "山田太郎",
  "email": "yamada@example.com",
  "created_at": "2025-10-28T10:00:00Z",
  "updated_at": "2025-10-28T10:00:00Z"
}
```

#### 4. ユーザー作成
- **エンドポイント**: `POST /api/users`
- **説明**: 新規ユーザーを作成
- **リクエストボディ**:
```json
{
  "name": "田中一郎",
  "email": "tanaka@example.com"
}
```
- **レスポンス**:
```json
{
  "id": 3,
  "name": "田中一郎",
  "email": "tanaka@example.com",
  "created_at": "2025-10-28T11:00:00Z",
  "updated_at": "2025-10-28T11:00:00Z"
}
```

#### 5. ユーザー更新
- **エンドポイント**: `PUT /api/users/:id`
- **説明**: 既存ユーザー情報を更新
- **パスパラメータ**: `id` (integer)
- **リクエストボディ**:
```json
{
  "name": "田中次郎",
  "email": "tanaka2@example.com"
}
```
- **レスポンス**:
```json
{
  "id": 3,
  "name": "田中次郎",
  "email": "tanaka2@example.com",
  "created_at": "2025-10-28T11:00:00Z",
  "updated_at": "2025-10-28T12:00:00Z"
}
```

#### 6. ユーザー削除
- **エンドポイント**: `DELETE /api/users/:id`
- **説明**: 指定IDのユーザーを削除
- **パスパラメータ**: `id` (integer)
- **レスポンス**:
```json
{
  "message": "User deleted successfully"
}
```

## 12. トラブルシューティング

### よくある問題と解決方法

#### 1. データベース接続エラー
**症状**: `connection refused` エラー
**解決策**:
```bash
# DBコンテナの状態確認
docker-compose ps

# DBコンテナのログ確認
docker-compose logs db

# DBコンテナの再起動
docker-compose restart db
```

#### 2. ポート競合エラー
**症状**: `port is already allocated` エラー
**解決策**:
```bash
# 使用中のポートを確認
lsof -i :8080
lsof -i :5432

# .envファイルでポート番号を変更
```

#### 3. モジュール依存関係エラー
**症状**: `module not found` エラー
**解決策**:
```bash
# go.modとgo.sumを削除して再生成
docker-compose run --rm api sh -c "rm -f go.mod go.sum && go mod init sample-project && go mod tidy"
docker-compose up -d --build
```
