## スマートコントラクト仕様

## 概要

スマートコントラクト仕様は、一連の要件から生成され、スマートコントラクトが適切に定義され、期待どおりに機能することを保証します。

## サンプル

### StickerNFT.sol 設計ドキュメント

---

#### 概要

`StickerNFT.sol` スマートコントラクトは、Ethereumブロックチェーン上で展開されるERC721トークンであり、ステッカーをテーマにしたNFTコレクション向けに特化した機能を備えています。OpenZeppelinのアップグレード可能なコントラクトフレームワークを活用し、将来の拡張性を確保しながら堅牢なセキュリティを維持します。

#### 仕様

##### アップグレード機能

- **フレームワーク**: OpenZeppelinのアップグレード可能なコントラクトフレームワークを使用  
- **プロキシパターン**: `Transparent Proxy Pattern` または `Universal Upgradeable Proxy Standard (UUPS)` のいずれかを使用し、効率性とセキュリティを考慮  

##### 供給制限

- **最大供給量**: ミント可能な最大トークン数を定義し、希少性を確保  
- **ミント制約**: 最大供給量を超えないよう、ミント時にチェックを実施  

##### ミントプロセス

- **機能**: `mint` 関数を実装し、`tokenId`（NFTの一意識別子）と `tokenUri`（メタデータURI）を受け取る  
- **アクセス制御**: `Ownable` コントラクトを活用し、オーナーのみが `mint` を実行可能にする  
- **一意性確保**: 各NFTの `tokenId` はユニークであり、既存のIDをミントしようとするとエラーを発生  

##### ホワイトリスト機能

- **ホワイトリスト管理**: 特定のアドレスのみがNFTを受け取れるよう制限  
- **転送制限**: `transferFrom` および `safeTransferFrom` 関数内で、ホワイトリストに登録されたアドレスのみトークンを受け取れるようにチェック  
- **管理機能**: オーナーがホワイトリストにアドレスを追加・削除できるよう関数を実装  

#### 機能概要

##### スマートコントラクトの要素

- **ベースコントラクト**: `ERC721Upgradeable` をベースとし、アップグレード機能を付与  
- **アクセス制御**: `OwnableUpgradeable` を利用し、オーナー権限の管理を実装  
- **メタデータと列挙機能**: `ERC721URIStorageUpgradeable` と `ERC721EnumerableUpgradeable` を活用し、メタデータの保存とトークンの列挙を可能に  

##### 主要関数

- `initialize`: コンストラクタの代替として機能し、オーナー設定や最大供給量の初期化を行う  
- `mint`: オーナーのみが呼び出せるNFTミント関数  
- `addToWhitelist`: アドレスをホワイトリストに追加する関数  
- `removeFromWhitelist`: アドレスをホワイトリストから削除する関数  
- `transferFrom` および `safeTransferFrom`: 受取アドレスがホワイトリストに登録されていることを確認  

##### イベント定義

- `Minted`: 新規NFTがミントされた際に発火し、`tokenId` および `tokenUri` を記録  
- `WhitelistUpdated`: ホワイトリストが更新された際に発火し、変更されたアドレス情報を記録  

#### セキュリティ考慮点

- **アクセス制御**: OpenZeppelinの `Ownable` および `Access Control` を使用し、不正アクセスを防止  
- **アップグレード安全性**: マルチシグ管理を導入し、アップグレード時のリスクを最小化  
- **コントラクト間の安全なやり取り**: `ReentrancyGuard` を適用し、チェック・エフェクト・インタラクション（CEI）パターンを徹底  

#### デプロイおよびテスト

`StickerNFT.sol` スマートコントラクトのデプロイ手順:

1. NFT機能を実装したロジックコントラクトをデプロイ  
2. ロジックコントラクトを指すプロキシコントラクトをデプロイ  
3. プロキシ経由で `initialize` を実行し、コントラクトの初期状態を設定  

テストは、ローカルブロックチェーン環境（Ganache など）や、Rinkeby や Ropsten などのテストネット上で実施し、上記のすべての機能を検証します。自動テストは Truffle や Hardhat を使用して作成します。

徹底したテストの後、コントラクトは Ethereum メインネットにデプロイされます。アップグレード機能により、既存のエコシステムを妨げることなく、必要に応じて改善や新機能の追加が可能になります。
