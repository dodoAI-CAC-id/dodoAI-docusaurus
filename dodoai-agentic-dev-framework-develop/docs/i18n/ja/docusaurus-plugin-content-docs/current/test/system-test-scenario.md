## システムテストシナリオ

## 概要

システムテストシナリオは、SSツールの機能が要件を満たし、現実の使用を効率的に処理できることを確認するためにテストされる特定の条件です。このガイドは、SSツールのパフォーマンス、信頼性、およびユーザーエクスペリエンスを検証するための包括的なシステムテストシナリオを作成するのに役立ちます。

### 目的
1. SSツールの関連するテストシナリオを特定し、作成する。
2. 一般的なケースとエッジケースの両方を網羅する。
3. 異なる条件下でのシステムの挙動を検証する。
4. 効率的な欠陥の特定と解決を促進する。

### 前提条件
1. **要件の理解**: SSツールの機能要件と非機能要件について十分な理解を持つこと。
2. **テスト環境**: 本番環境に類似したテスト環境を設定する。
3. **ツールとリソース**: テストツール、バージョン管理、ドキュメンテーション、トラッキングシステムにアクセスする。

### システムテストシナリオの作成手順

#### 1. **システムテストスプレッドシートを作成する**
   - Googleドライブ: [リンク](https://drive.google.com/drive/u/0/folders/1FpflrG5xnI45tUBSwmk4yGtHMeib63JW).
   - テンプレート: [リンク](https://docs.google.com/spreadsheets/d/1VAxdjk2Z78qCM5vyw3UUcol3pAhEfOE29ZivAdjeWfQ/edit#gid=0).

#### 2. **文書に基づいてテストシナリオを作成する**
   - ワイヤーフレームを参照し、要件定義とシステム設計を明確にする: [リンク](https://miro.com/app/board/uXjVNhdn81M=/).
   - 詳細な機能要件を記載した**スクリプトスカルプター(LLM)仕様/設計文書**を確認: [リンク](https://docs.google.com/document/d/1RJWlEsyMTTdm4l5ja_uJN-xteCyY-aHPkPc-Pl-j7lY/edit#heading=h.3jtkuymjv6xi).
   - 各機能の詳細なフローを示すユーザーストーリーリストに基づく: [リンク](https://docs.google.com/spreadsheets/d/1kURKsfy2XeguJnUo4cXGgNYaTeWzJ2WsMLAO5uYoSJo/edit?gid=1310947896#gid=1310947896).
   - フロントUIシステムデザインを参照: [リンク1](https://miro.com/app/board/uXjVKaNTLsQ=/) & [リンク2](https://miro.com/app/board/uXjVMvA1mqE=).

#### 3. **詳細なテストシナリオを作成する**
   - **通常のシナリオ**: すべてが予定通りに動作する一般的なユーザーインタラクション。
   - **代替シナリオ**: 予期しないパスや代替行動を取る状況。
   - **エッジケース**: システムが予測できない動作をする可能性のある稀な条件や極端な条件。
   - **ネガティブシナリオ**: 無効な入力や行動に対処するシステムの能力をテストする状況。

### テストシナリオのサンプル

#### コア対話技術
1. **自由に自分のプロンプトを入力**
   - **シナリオ**: ユーザーが直接の質問をする（例: "フランスの首都はどこですか？"）
   - **期待される結果**: SSツールが正しく応答する（例: "フランスの首都はパリです。"）

2. **プルリクエストのレビュー**
   - **シナリオ**: ユーザーがSSツールにプルリクエストのレビューを依頼する
   - **期待される結果**: SSツールが問題の特定と各種の課題を方法的に特定し整理する。潜在的なバグ、性能ボトルネック、セキュリティ上の脆弱性、コーディング標準の遵守、ソフトウェア設計上のベストプラクティスを含む。

#### 特殊機能
1. **UI画像を使用した問題の登録**
   - **シナリオ**: Githubで問題を登録する。提供された入力とUI画像（もしあれば）に基づいて問題テンプレートの内容を更新する
   - **期待される結果**: 出力は問題テンプレートに従い、マークダウンで記述される。完全なファイルの情報以外の出力は不要。

2. **システム要件**
   - **シナリオ**: ユーザーストーリーのリストからシステム要件を生成する。
   - **期待される結果**: 出力は以下のフォーマットであるべきです。以下のプロセスの流れが箇条書きになっています。

3. **シーケンスダイアグラム**
   - **シナリオ**: システム要件と概念データモデルを入力として、PlantUML形式でシーケンスダイアグラムを作成してください。
   - **期待される結果**: SSツールが期待通りのシーケンスダイアグラムを作成する。

4. **モデルユニットテスト**
   - **シナリオ**: Dynamooseを使用してNode.js Expressアプリケーションのモデル層のユニットテストを作成し、モデル機能を検証し、100%のテストカバレッジを達成することを目指す。
   - **期待される結果**: モデル層の詳細なユニットテストスイートを作成することを目的とする。

5. **UIページとコンポーネント**
   - **シナリオ**: Flutterアプリのソースコードをリファクタリングし、改善する。
   - **期待される結果**: SSツールがUIページとテストコードのためのフルDartコードを返し、コードがFlutterプロジェクトに統合可能であることを確認する。

6. **プロフェッショナルユーザーインタラクション**
   - **シナリオ**: Ethereumブロックチェーン上に構築されたERC721トークンであるスマートコントラクト `StickerNFT.sol` の設計文書を作成する。
   - **期待される結果**: マークダウン形式で仕様と機能を詳細に記述した設計文書を作成する。

#### エッジケースとネガティブシナリオ
1. **曖昧な入力の処理**
   - **シナリオ**: ユーザーが曖昧なクエリを入力する（例: "それについて教えてください。"）
   - **期待される結果**: SSツールは明確化を求めるか、前のコンテキストに基づいて一般的な応答を提供する。

2. **無効な入力**
   - **シナリオ**: ユーザーが意味不明またはサポートされていない言語を入力する（例: "asdkfadhh"）
   - **期待される結果**: SSツールは適切なフォールバックメッセージで応答する。

#### パフォーマンスとセキュリティ
1. **負荷対応**
   - **シナリオ**: 複数の同時クエリによる高負荷をシミュレートする。
   - **期待される結果**: SSツールはクラッシュすることなく応答の質と速度を維持する。

2. **データプライバシー**
   - **シナリオ**: 個人情報を含むユーザークエリ。
   - **期待される結果**: SSツールがデータを安全に処理し、機密情報を露出しないことを確認する。

### シナリオの文書化
- **シナリオID**: 各テストシナリオの一意の識別子。
- **前提条件**: シナリオ実行前に必要なセットアップ。
- **テストステップ**: シナリオ実行の具体的な手順。
- **期待される結果**: 各ステップに対する期待される結果。
- **実際の結果**: テスト中の実際の結果。
- **状態**: テスト後の合否。
- **コメント**: その他の観察や備考。

### ベストプラクティス
1. **シナリオに優先順位をつける**: 高影響および高頻度のユースケースにまず焦点を当てる。
2. **定期的に更新する**: 新機能が追加されたり、既存のものが修正された場合、シナリオを更新する。
3. **自動化**: 頻繁に実行される、または複雑なシナリオを可能な限り自動化して時間を節約する。
4. **ピアレビュー**: 他のチームメンバーによってシナリオをレビューしてもらい、完全性と正確性を確保する。

### 結論
SSツールのための包括的なシステムテストシナリオを作成することで、システムが様々な実世界の条件とユーザーインタラクションを完全に検証されることを保証します。このガイドに従うことで、ChatGPTの機能、パフォーマンス、セキュリティのさまざまな側面を体系的にカバーし、堅牢で信頼性の高いAIソリューションを提供できます。
