# ガイド: インフラストラクチャストレージ設計の定義

- このガイドを使用して、クラウドネイティブとマイクロサービス環境でのストレージアーキテクチャのすべての要件、ポリシー、設定を明示的に定義してください。
- 記述すべき内容のみに焦点を当ててください—ストレージクラス選択、ライフサイクル、バックアップ、パフォーマンス、セキュリティ、アクセス制御、監視。
- 一般的な説明は避け、すべての設計項目を列挙してください。

---

## 定義すべき内容

### 1. オブジェクトストレージ（S3、Blobなど）

- **バケット戦略:**  
  - すべての必要なバケット（アプリケーションデータ、アセット、ログ、バックアップ）の名前と役割。
  - バージョニング、暗号化（SSE-S3/SSE-KMS）、アクセスポリシー（プライベート/制限/パブリック）、CDN統合。
  - ライフサイクル管理：低頻度アクセス、アーカイブ（Glacier）への移行、削除/有効期限設定。

### 2. ブロックストレージ（EBSなど）

- **ボリュームタイプとチューニング:**  
  - 使用ケースを含むすべての必要なEBS（または同等）タイプを詳述：ルート、アプリケーションデータ、DB。
  - サイズ、IOPS、スループット、暗号化状況、保持/リサイクルポリシー。

### 3. ファイル/共有ストレージ（EFSなど）

- **EFS/NFS設定:**  
  - ファイルシステム名、アクセスポイント、パフォーマンス、スループットモード、バックアップ設定。
  - マウントターゲット（AZ/サブネット）、セキュリティグループ制御。

### 4. キャッシングストレージ

- **ElastiCache/Redis/Memcached設計:**  
  - エンジン/バージョン、クラスターサイズ/トポロジー、ノードあたりメモリ、マルチAZ/自動フェイルオーバー。
  - 保持/バックアップ、エビクション/TTL、パフォーマンス戦略。

### 5. データライフサイクルと階層化

- **ライフサイクルポリシー:**  
  - 移行（例：S3 Standard → IA → Glacier/Deep Archive）、保持期間。
  - ログ、バックアップ、データバケットの自動削除とアーカイブルール。
- **インテリジェント階層化:**  
  - 自動監視、アーカイブ有効化、最小ストレージ期間、コスト最適化設定。

### 6. バックアップと災害復旧

- **バックアップポリシー:**  
  - 頻度、保持期間、クロスリージョンコピー、手動対自動スナップショットの役割。
- **復旧手順:**  
  - データベース、アプリケーションデータ、ファイルの復元手順；フェイルオーバー/DRリージョン戦略。

### 7. パフォーマンス最適化

- **チューニングパラメータ:**  
  - IOPS設定、スループット、バルク/アップロード最適化（例：マルチパート）、転送高速化、パフォーマンス制限。
- **キャッシングとクエリ最適化:**  
  - データベースキャッシュ設定、キャッシュヒット率ターゲット、コストパフォーマンスガイドライン。

### 8. セキュリティとアクセス

- **暗号化:**  
  - 保存時および転送時の暗号化要件（デフォルトオン、機密データの顧客管理キー）。
- **アクセスポリシー:**  
  - S3バケット/IAMポリシー；最小権限、パブリックアクセスブロック、MFA削除のコンプライアンス。
- **監査と監視:**  
  - タイプ別ストレージメトリクスリスト（使用率、エラー、レイテンシ、コスト）、アラートしきい値、レポート要件。

---

**注意:**  
すべてのストレージ設計要件とポリシーは、バージョン管理されたアーティファクトとして文書化・追跡される必要があります。ストレージ、ワークロード、またはセキュリティコンテキストの変化に応じて更新してください。
