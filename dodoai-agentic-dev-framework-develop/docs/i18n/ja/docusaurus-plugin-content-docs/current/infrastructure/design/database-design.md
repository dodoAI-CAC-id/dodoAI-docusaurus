# ガイド: インフラストラクチャデータベース設計の定義

- このガイドを使用して、マイクロサービスとクラウドネイティブ環境でのインフラストラクチャのデータベースアーキテクチャと必要な実践を明示的に定義してください。
- 実装詳細や一般的な議論は含めず、設計、選択、管理すべき内容を指定してください。

---

## 定義すべき内容

### 1. データベース設定

- **RDSとマネージドDB:**  
  - エンジンとバージョン
  - インスタンスタイプ/クラス、ストレージ（サイズ/タイプ）、マルチAZとバックアップ設定
  - リードレプリカ数、クロスAZ設定、コネクションプーリングツール/設定
- **Aurora:**  
  - エンジン/バージョン、役割ごとのインスタンス数（ライター、リーダー）、サーバーレス設定、グローバルDBレプリケーション/リージョン、自動バックアップとポイントインタイム復旧パラメータ

---

### 2. NoSQL/データストア設計

- **DynamoDBまたは同等:**  
  - テーブル定義、パーティション/ソートキー戦略、属性リスト、TTLフィールド、課金モード（オンデマンド/プロビジョンド）、インデックス（GSI、LSI）、スループット設定
- **キャッシング（ElastiCache/Redis/Memcached）:**  
  - クラスターサイズ、ノードタイプ、メモリ設定、フェイルオーバー/HA、保持とバックアップ、エビクションとTTLポリシー、使用ケース区別（セッション、クエリ、オブジェクトキャッシュなど）

---

### 3. セキュリティとアクセス制御

- **暗号化:**  
  - 保存時：ストアごとの有効化とKMSキー使用
  - 転送時：SSL/TLS要件、最小TLSバージョン、証明書検証
- **アクセス:**  
  - IAM DB認証、VPC/ネットワークグループ割り当て、ユーザー役割/権限設計、プライベートサブネット使用、管理者MFA、最小権限実施

---

### 4. パフォーマンスと最適化

- **DBチューニング:**  
  - バッファ/キャッシュ/ワークメモリのリソース配分、接続設定、クエリログ/分析、最大接続数。
- **インデックス戦略:**  
  - PK/FK/クエリのインデックス、監視、ワークロードに基づく未使用インデックスの削除または追加の定期レビュー。

---

### 5. バックアップ、復旧、DR

- **バックアップ:**  
  - 各DB（SQL/NoSQL/キャッシュ）の頻度/タイプ（自動/手動）、クロスリージョンコピー、スナップショットポリシー。
- **復旧:**  
  - 環境/データクラスごとのRTO/RPO、必要な復旧/テスト頻度、フェイルオーバー手順と必要な監視。

---

### 6. 監視とアラート

- **データベースメトリクス:**  
  - 必要なメトリクス（例：IOPS、CPU、メモリ、レイテンシ、ラグ、エラー率）をリストアップ。
  - すべての本番データストアのアラートしきい値を定義。
- **パフォーマンスインサイト:**  
  - 必要に応じてツール/機能（例：RDS Performance Insights）の使用、保持、監視実践を実施。

---

### 7. データ移行

- **移行計画:**  
  - ツール（例：DMS）、移行フローフェーズ（スキーマ、初期ロード、変更キャプチャ、切り替え）、ロールバック要件
- **検証:**  
  - プロセスと技術（行数、チェックサム、テストシステム検証）

---

### 8. コスト最適化

- **インスタンス/ストレージ選択:**  
  - リザーブドインスタンス、適正サイジング、可変ワークロード用の柔軟/サーバーレスオプション採用の選択とレビュー
  - ストレージ/アーカイブ/圧縮戦略、スナップショットと古いデータの削除または保持ポリシー

---

**注意:**  
上記のすべての要件は、インフラストラクチャ設計文書の一部としてリスト化、レビュー、バージョン管理される必要があります。可能な限り、技術、ワークロード、または組織リスクの変化に応じて更新してください。
