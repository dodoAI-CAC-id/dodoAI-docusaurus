# ガイド: インフラストラクチャTerraformテンプレートとファイルドキュメント

- このガイドを使用して、Infrastructure as Code（IaC）設定で使用される各Terraformファイルの構造、内容、目的を指定してください。
- 存在する必要があるものと各ファイルの意図/目的のみを文書化してください。
- コードサンプルは提供せず、保守性とオンボーディングのための簡潔で機能的なファイル説明を提供してください。

---

## 定義すべき内容

### 1. リポジトリとディレクトリ構造

- すべてのTerraform（*.tf）ファイルとディレクトリのディレクトリレイアウトを指定してください。
- 各ファイルが単一の責任（ネットワーク、コンピュート、サービスロール、変数、出力など）を果たすことを確保してください。
- 構造例（プロジェクトに応じて調整）：

```
├── be.tf
├── ecs-cluster.tf
├── fe.tf
├── locals.tf
├── main.tf
├── output.tf
├── service-roles.tf
├── variables.tf
└── vpc-alb.tf
```

### 2. ファイル別定義

各ファイルについて以下を定義してください：

- **ファイル名**:  
  - `be.tf`: バックエンド/サーバー固有の設定（インフラストラクチャとアプリケーション）
  - `ecs-cluster.tf`: AWS ECS（Elastic Container Service）クラスター設定とリソース
  - `fe.tf`: フロントエンドサーバー設定と設定
  - `locals.tf`: 再利用可能なローカル変数と共通データを宣言
  - `main.tf`: メインエントリーポイント；全体的なプロバイダー/リソース設定を調整
  - `output.tf`: 作成されたリソースに関する情報を公開する出力変数を宣言
  - `service-roles.tf`: サービス用のIAMロールとポリシー（例：ECSタスク、Lambdaなど）
  - `variables.tf`: 入力変数宣言、タイプ、デフォルト、制約、ドキュメント
  - `vpc-alb.tf`: VPC、サブネット、ルートテーブル、ALB（ロードバランサー）設定；セキュリティグループルール

- **目的/意図:**  
  - 各ファイルが設定/制御する内容（コンピュート、ネットワーキング、セキュリティ、モジュール性など）を要約してください。

- **内容:**  
  - ファイルに含まれる高レベルのリソースタイプと関係。
  - 複雑な設定の関連ドキュメントへの参照またはリンク。

- **関係:**  
  - 他に依存する、または他から参照されるファイル/モジュールを明示的に記載してください（例：他の設定で使用される出力）。

---

### 3. ドキュメントとメンテナンス

- すべてのファイルとモジュールについて、ファイルの上部または追跡されるREADMEに短い説明的なドキュメントブロックがあることを確保してください。
- インフラストラクチャ設計をリファクタリングまたは変更する際は、ファイル目的の説明を最新に保ってください。

---

**注意:**  
このドキュメントを常にバージョン管理し、更新してください。これにより、インフラストラクチャコードベースのすべての変更について、一貫したコラボレーション、オンボーディング、レビューが可能になります。
