# ガイド: インフラストラクチャプロビジョニングファイル（Terraform）の定義

- このガイドを使用して、インフラストラクチャプロビジョニングで使用されるすべてのTerraformファイルを指定してください。
- 各ファイルの目的、内容、関係を明確に定義してください。
- 実装サンプルや一般的な説明は含めず、何が存在する必要があり、なぜ必要なのかのみを文書化してください。

---

## 定義すべき内容

### 1. ファイルインベントリ

- プロビジョニングに必要なすべてのTerraformファイル、スクリプト、モジュールをリストアップしてください。
  - 各ファイルについて以下を提供してください：
    - **ファイル名（相対パス）:**
    - **目的/役割:** （例：プロバイダー設定、リソース定義、変数宣言、出力、バックエンドなど）
    - **主要な依存関係:** （ファイル/モジュールが他に依存している、または他から含まれている場合）
    - **環境/適用性:** （dev、staging、prod、または共有）

### 2. ファイル構成と構造

- すべてのプロビジョニングファイルとモジュールのディレクトリ/サブディレクトリ構造。
- ファイルとモジュールの命名規則（例：`main.tf`、`variables.tf`、`outputs.tf`、`backend.tf`、`/modules/`）。
- 環境固有ファイルと共有ファイルを分離するポリシー。

### 3. 更新とバージョニング実践

- 変更を追跡する方法/場所（VCS標準、コードレビュー、タグ付け）。
- 追加、削除、または重要な変更をコードコメントまたは変更ログで直接文書化する要件。

---

**注意:**  
インフラストラクチャとプロビジョニングロジックが進化するにつれて、このインベントリと説明を生きたものとしてバージョン管理してください。Docusaurusで実際の実装を文書化せず、最新の説明と構造のみを維持してください。
