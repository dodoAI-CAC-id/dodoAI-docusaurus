# ガイド: マイクロサービス単体テスト計画

- このガイドは、C0、C1などの標準を使用した明示的なテストカバレッジメトリクスに焦点を当てて、マイクロサービスの単体テストを計画する際に指定すべき内容を定義します。
- サンプルコードやテスト理論は含めず、計画項目、コード構造、および必要なカバレッジメトリクスのみに焦点を当てます。

---

## 定義すべき内容

### 1. テストスコープとカバレッジ

- 各マイクロサービスの単体テストでカバーすべきすべてのレイヤーを特定します：
  - **コントローラーレイヤー:** 入力検証、リクエスト処理、エラーパス
  - **サービスレイヤー:** ビジネスロジック、エラーロジック、オーケストレーション
  - **リポジトリ/DAOレイヤー:** 永続化ロジック、マッピング
  - **ドメインモデル:** エンティティと値オブジェクトのルール/検証

- 各レイヤーとコンポーネントについて、定義されたカバレッジメトリクスを満たすために必要な単体テストケースを指定します。

---

### 2. カバレッジメトリクス（C0、C1など）

- **C0（ステートメントカバレッジ）:**
  - すべての実行可能ステートメントが少なくとも1つのテストケースで実行されることを確保します。
  - **目標:** すべてのコードで80%以上；重要なモジュールでは100%。

- **C1（ブランチカバレッジ）:**
  - 決定構造のすべてのブランチ（例：if、else）が少なくとも1回は実行されることを確保します。
  - **目標:** すべてのコードで70%以上；セキュリティまたはロジック重要なコードでは100%。

- **C2（パスカバレッジ）[オプション/上級]:**
  - 各モジュールを通るすべての線形独立パスがテストされることを確保します。
  - 高度に重要または複雑なモジュールのみに使用します。

- **MC/DC（修正条件/決定カバレッジ）[安全重要システム用]:**
  - 決定内のすべての個別条件が独立して結果に影響することを確保します。
  - 規制要件または最高保証を必要とするモジュールに使用します。

- 各モジュールに必要なカバレッジメトリクスと、カバレッジの測定方法（例：JaCoCo、Istanbul、Coverage.pyなど）を明確に文書化します。

---

### 3. テスト構成

- フィーチャーとレイヤーごとにテストを整理し、本番コード構造をミラーリングします。
- 各クラス/コンポーネントとレイヤー（コントローラー/サービス/モデル）に対して別々のテストファイルを使用します。

---

### 4. 必要なツール

- 以下のツールを指定します：
  - テスト実行（例：JUnit、PyTest）
  - モック/スタブ（例：Mockito）
  - カバレッジ測定（例：Java用JaCoCo、Python用coverage.py）

---

### 5. ポリシーとレビュー

- テストはコード変更に応じて維持・更新される必要があります。
- コードレビューでは、任意のモジュールでC0/C1メトリクスの最小値を下回る場合、マージをブロックする必要があります。

---

**注意:**  
これらのカバレッジメトリクスとポリシーは、エンドユーザードキュメントではなく、コードベースとCIパイプラインで実施されるべきです。
