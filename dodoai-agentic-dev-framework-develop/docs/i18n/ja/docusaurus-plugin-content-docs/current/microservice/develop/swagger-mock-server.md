# ガイド: Swagger モックサーバー

- このドキュメントは、開発ワークフローの一部としてSwagger モックサーバーの使用を定義するガイドです。
- DocusaurusドキュメントでSwagger モックサーバーのユーザー向けドキュメントを作成しないでください。
- すべての使用方法、設定、開発者ワークフローをコードベースと開発環境のドキュメントで定義してください。

---

## 定義すべき内容

### 1. モックサーバーの使用

- 実際のバックエンドAPIがまだ利用できない場合、フロントエンド開発者はSwagger モックサーバーをバックエンドの代替として使用する必要があります。

### 2. API仕様の場所

- 各マイクロサービスのすべてのSwagger/OpenAPI（YAMLまたはJSON）ファイルは、リポジトリ内の専用ディレクトリ（`/static/swagger/`など）で維持する必要があります。

### 3. サーバー実行/セットアップ手順

- 各API仕様のモックサーバーの実行方法を定義してください（例：Prism CLIまたはDockerを使用）。
- フロントエンド/クライアントコードが正しいエンドポイントをターゲットできるように、ポート、ベースURL、ファイルマッピングを指定してください。

### 4. 環境統合

- 環境変数または設定を構成することで、フロントエンドおよび他のクライアントがモックエンドポイントに切り替える方法を文書化してください。
- すべてのAPIパスとモックレスポンスが本番環境で使用されるOpenAPI定義に従うことを確保してください。

### 5. チームワークフロー

- 実際のAPIがデプロイされるまで、フロントエンド/手動/統合/APIテストでモックサーバーの使用を要求してください。
- APIの進化に応じて仕様とモックデータを更新し続けてください。
