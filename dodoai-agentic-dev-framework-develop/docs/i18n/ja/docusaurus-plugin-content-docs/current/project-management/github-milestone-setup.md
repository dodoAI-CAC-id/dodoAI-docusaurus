## GitHub マイルストーンの設定

## GitHub にマイルストーンを登録する
Notion に登録されたレベル 1 の開発タスクを GitHub のマイルストーンとリンクさせます。  
マイルストーンの終了日は、Notion のレベル 1 開発タスクの終了日と同じに設定してください。  

各レベル 1 のタスクは、対応するマイルストーンに直接リンクする必要があります。  
より詳細な開発タスク（レベル 2）は、GitHub の Issue として定義されます。  

登録すべきタスクについては SDF を参照してください。  
[Miro SDF](https://miro.com/app/board/uXjVNhdn81M=/?moveToWidget=3458764589861350205&cot=14)

## GitHub に Issue を登録する
SDF に基づいてタスクを登録する際は、以下のガイドラインに従ってください。  
- 各機能ごとに Issue を作成するのが面倒な場合は、Google Apps Script（Gas）を使用した Issue 登録ツールが利用可能です。  [GitHub Issue Creator](https://docs.google.com/spreadsheets/d/1tVnxJzJpan8ToeOxC2yEouGM6JQuWBAFohxTXu7Bxi0/edit?gid=912739404#gid=912739404)  
- 使用したい場合は、チームのリードエンジニアに問い合わせてください。  

- **要件定義・設計タスク**  
  - プロジェクト全体で 1 つのタスクがあれば十分です。  
- **開発タスク**  
  - 各機能ごとに登録する必要があります。  

### **Issue のサイズに関する重要な注意点**
58 では、開発の大部分を AI を活用して行います。AI エージェントの効率を最大化するため、以下のルールを遵守してください。  
- **1 Issue = 1 PR**。Issue の開発範囲が大きすぎると、レビューの効率が低下し、最終的に品質が低下します。  
- **1 ファイルのステップ数は 100 行未満が理想**。常に完成度の高いコードを出力することで、AI エージェントによる自動化が可能になります。  ファイルサイズを最小限に抑えることを心がけましょう。 ステップ数が大きくなった場合は、モジュール化できるかを検討し、ファイルを分割してください。これにより、保守性も向上します。
