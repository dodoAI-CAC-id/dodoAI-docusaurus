## スプリントプランニングとレトロスペクティブ

## スプリントの期間

- 開発は1週間のスプリントで行います。

## GitHubとGitHub Projectsの使用に関する主なルール

### 1. イテレーション機能の利用

- **イテレーション**機能を使用して、スプリントを定義します。

### 2. GitHub Wikiの使用

以下の情報をドキュメント化するためにGitHub Wiki機能を使用してください：

#### 前回のスプリントレトロスペクティブ

- 成果をレビューし、各メンバーのストーリーポイントを記録します。

#### KPT（Keep, Problem, Try）

- 各メンバーは自分のKPTを簡単に記録します。
- KPTの説明を含め、K、P、Tそれぞれについて2分間でその場で記入します。
- Miroでスプリントレトロスペクティブ用のボードを作成し、そこでKPTを実施します。

#### 週間目標

- 週間目標のマイルストーンを定義します。

#### 個別の課題

- 各メンバーに割り当てられた課題をリスト化します。

### KPTの説明

- **K（Keep）**: 続けるべきこと
- **P（Problem）**: 発生した問題
- **T（Try）**: 次回試すべきこと
