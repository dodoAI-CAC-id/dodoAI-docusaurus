## GitHubプロジェクトの更新

イシューが登録されたら、プロジェクトマネージャー (PM) がそれに応じてGitHubプロジェクトを更新する必要があります。このページでは、GitHubプロジェクトを更新するためのガイドラインを提供しており、イテレーション、ストーリーポイント、開始日、および締切日の設定を含みます。

## GitHubプロジェクトを更新する手順

1. **イテレーション**
   - 関連するイテレーションにイシューを割り当てます。これにより、特定の期間にわたるイシューの進捗を追跡するのに役立ちます。
   - イテレーションはスプリントと等しく、1週間の期間に設定されています。つまり、1週間 = 1イテレーション。

2. **ストーリーポイント**
   - ストーリーポイントを割り当てて、イシューを完了するために必要な労力を見積もります。ストーリーポイントは、イシューを解決するのに必要な複雑さと労力を理解するのに役立ちます。
   - ストーリーポイントはタスクのサイズを示します。2の倍数（1、2、4、8、16）を使用します。
   - ストーリーポイントが32以上の場合、それはタスクが大きすぎることを示しています。必ず小さなタスクに分割してください。（**注記**: このポイントは強調されています。）

3. **開始日**
   - イシューの開始日を設定します。これは、イシューの作業が開始される予定の日付です。

4. **締切日**
   - イシューの締切日を設定します。締切日がマイルストーンの完了日を超えないようにしてください。締切日はイシューを解決するための期限を示します。
   - *注記:* 締切日はマイルストーンの完了日内に設定され、時間通りの納品を保証します。

## 例

これらのフィールドを更新する方法の例は以下の通りです：

- イテレーション: スプリント5
- ストーリーポイント: 3
- 開始日: 2023-09-01
- 締切日: 2023-09-07

これらのガイドラインに従うことで、すべてのイシューが効率的に追跡および管理され、スムーズなプロジェクト管理と時間通りの納品が可能になります。

## キーポイント

- イテレーション: 追跡のために関連するイテレーションに割り当てる。
- ストーリーポイント: 必要な労力を見積もる。
- 開始日: イシューの予定開始日。
- 締切日: イシューを解決するための期限；マイルストーンの完了日を超えないようにする。

このアプローチはプロジェクトを軌道に乗せ、すべてのチームメンバーが自分の責任と締切日を理解するのを確実にします。
