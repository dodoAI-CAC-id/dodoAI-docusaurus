## イシューレジストレーション

このドキュメントは、GitHubでのイシューレジストレーションプロセスを概説し、各タスクに必要な情報を詳述しています。

## 目的

ここで提供するガイドラインにより、GitHubに登録される各イシューが明確で実行可能とされ、効率的な問題処理が促進されます。

## イシューのステータス

- **Todo**  
  バックログまたは開始準備が整っていない。
- **In Progress**  
  現在開発中またはサポート中。
- **In Review**  
  同僚またはチームリードによってレビュー中。
- **Done**  
  関連するプルリクエスト (PR) とともに完了。

**注記**: 通常、関連するPRがマージされると、イシューは自動的にクローズされます。この設定は注意して取り扱ってください。

## ルール

1. **イシュータイトル**
   - イシューの内容を正確に反映する簡潔で明確なタイトルを提供してください。

2. **目的 (Goal)**
   - イシューの目的を明確に記載してください。
   - 例: 「このイシューの目的は、ユーザー体験を妨げるログインバグを修正することです。」

3. **仕様 (Spec)**
   - **新機能**: 新機能の詳細な要件をリストにします。
   - **バグ**: 再現手順、期待される動作、および実際の動作を記載します。

4. **プロジェクト**
   - 関連するプロジェクトを選択してください。

5. **関連リンクとリソース**
   - 関連ドキュメント、リンク、スクリーンショット、コードスニペットなどを含めてください。

6. **チェックリスト (必要に応じて)**
   - ステップまたはタスクを概説するチェックリストを使用します。
   - 例:
     - [ ] バグを再現する
     - [ ] コードを修正する
     - [ ] ユニットテストを書く
     - [ ] コードレビューを実施する

### 上記の詳細が入力されたら、「新しいイシューを送信」を選択して保存します。次に、以下のイシュー情報を設定してください：

1. **アサイニー**
   - イシューを担当するメンバーを指定します。
   - 例: `@username`

2. **ラベル**
   - バグ、機能要求、またはドキュメントなどの適切なラベルを適用します。
   - 例: `バグ, 高優先度`

3. **マイルストーン**
   - 該当する場合、イシューをマイルストーンに関連付けます。

## イシューテンプレート

### 新機能テンプレート

```markdown
# イシュータイトル

## 目的 (Goal)
このイシューの目的は、[具体的な目標] を達成することです。

## 仕様 (Spec)
- 要件:
  1. [要件1]
  2. [要件2]
  3. [要件3]

## プロジェクト
- プロジェクト: [プロジェクト名]

## 関連リンクとリソース
- [関連するドキュメントとリンク]

## チェックリスト (必要に応じて)
- [ ] [タスク1]
- [ ] [タスク2]
- [ ] [タスク3]
```
