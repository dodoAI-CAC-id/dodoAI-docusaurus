## プルリクエスト手続きのドキュメント

## 目的 (Goal)

このドキュメントの目的は、GitHubでプルリクエスト (PR) を作成するための詳細な手順を提供することです。これにより、開発者がコード変更の一貫したプロセスに従い、コラボレーションとコード品質を向上させます。

## プルリクエスト手続き

### はじめに

このセクションは、GitHubでプルリクエスト (PR) を作成するための詳細なステップを述べています。スムーズなワークフローを確保するための基本的な Git コマンドと PR 要件が含まれています。

### プルリクエストを作成する手順

1. **ソースコードの更新**:
   - ローカルリポジトリをメインブランチで最新の状態に保つ:

     ```sh
     git checkout develop
     git pull origin develop
     ```

2. **新しいブランチを作成 (Issue 画面を使用)**:
   - GitHub リポジトリの Issue 画面に移動します。
   - Issue から直接ブランチを作成する機能を使用します。これにより、コンテクストのリンクを漏洩せずに確保できます。
  
     <!-- ![ブランチを新規作成](../../../assets/create-new-branch.png) -->

   - 代替として、ワークフローが直接サポートされていない場合はコマンドラインを使用してブランチを作成できます:

     ```sh
     git checkout -b <branch-name>
     ```

   - **注意:** `git checkout -b <branch-name>` を使用すると、Issue へのリンクが漏洩するリスクがあるため推奨されません。代わりに、Issue 画面から直接ブランチを作成し、その後 Issue をチェックアウトするのが良いです。

3. **変更を加え、コミット**:
   - すべての変更ファイルをステージングエリアに追加:

     ```sh
     git add .
     ```

   - 必要に応じて特定のファイルを追加:

     ```sh
     git add <file>
     ```

   - 説明的なメッセージと共に変更をコミット:

     ```sh
     git commit -m "Describe your changes"
     ```

4. **ブランチを GitHub にプッシュ**:
   - リモートリポジトリにブランチをプッシュ:

     ```sh
     git push origin <branch-name>
     ```

   - **強制プッシュ (オプション)**: ローカルの変更をリモートブランチに上書きする必要がある場合:

     ```sh
     git push origin <branch-name> -f
     ```

   - **`-f` (force)**: リモートブランチでの非発展的マージの結果を招く場合でも、プッシュを強制します。他の人が行った変更を上書きする可能性があるため、慎重に使用してください。

5. **プルリクエストを作成**:
   - GitHub リポジトリページに移動。
   - 自分のブランチを選択し、新しいプルリクエストを作成。
   - PR タイトルと説明を記入。
   - レビュワーを選択し、PR を提出。

### PR 要件とガイドライン

- **PR タイトル**: タイトルが説明的で、PR の目的を要約していることを確認。
- **PR 説明**: 行った変更とレビュワーへの関連情報を明確に記述。
- **レビュー プロセス**: チームメンバーがレビューし、フィードバックを提供する時間を許可します。コメントや必要な変更に対応。

## レビューと承認

- ドキュメントの情報が全て完了してクリアであることを確認。
- ドキュメントの正確性と有用性を検証するためにチームメンバーからフィードバックを求める。

## 公開

- ドキュメントを GitHub リポジトリまたは内部ドキュメントプラットフォームに公開。
