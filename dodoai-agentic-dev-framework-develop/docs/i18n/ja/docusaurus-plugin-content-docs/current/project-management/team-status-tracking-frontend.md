## 概要

フロントエンドのチームステータストラッキングは、チームの活動や個々の貢献の進捗状況とパフォーマンスを監視、記録、評価するプロセスです。これには、タスクの割り当て、締め切り、完了状況、チームが直面する可能性のある障害の追跡が含まれます。

## 目標

フロントエンド開発チームが成長できるように、構造化された効果的なワークフローを作成します。進捗を追跡し、オープンなコミュニケーションを維持し、タスクを優先することで、チームはプロジェクトの目標に沿って進行し、高品質でタイムリーな成果物を確保できます。これらの目標は、チーム内での継続的な改善と協力の文化も促進します。

## はじめに

この文書は、GitHub Projectsを使用してフロントエンド開発タスクのステータスを追跡し、課題に締め切りを設定し、チームのステータスを効果的に管理するためのプロセスとベストプラクティスを概説しています。この方法論は、整合性を保ち、効率的なコミュニケーションを促進し、全体的な生産性を向上させます。

## ツールと設定

### GitHub Projects

GitHub Projectsは、タスクやワークフローを管理する強力なツールです。課題を作成し、締め切りを割り当て、タスクをラベルで分類して、ステータス（例：Backlog、Ready、In Progress、In Review、Done）を反映させることができます。

### 締め切り付きの課題

課題は個々のタスクや作業の進捗を追跡するために使用されます。課題に締め切りを設定することで、作業を優先し、タイムリーな納品を確保することができます。

### TeamStatus

TeamStatusは、チームメンバーに進捗を定期的に更新するために選ばれたツールです。これにより、ステータスの更新、ブロッカーの把握、成果の共有が可能です。

## ワークフロー

### 課題の作成と管理

1. **課題の作成**: 課題の作成と管理の詳細については、[課題登録](development-rules/issue-registration.md)をご参照ください。
2. **締め切りの設定**: 各課題に締め切りを設定して、優先順位を付け、タイムリーな完了を管理します。
   - 課題の右サイドバーに移動します。
   - `Due date`をクリックし、適切な日付を選択します。

### 進捗の追跡

1. **課題のステータス更新**: 課題のラベルをGitHubで変更して、現在の状態を反映させます：
   - `Backlog`: 新規で未着手の課題。
   - `Ready`: ピックアップ可能な課題。
   - `In Progress`: 現在進行中の課題。
   - `In Review`: レビュー中の課題。
   - `Done`: 完了した課題。

2. **コメントと更新の追加**: 課題に定期的にコメントを追加し、コンテキストや進捗を提供します：
   - 特定の進捗を記録します。
   - ブロッカーや要件をリストします。
   - 課題内でタスクを完了としてマークします。

### プルリクエストの取り扱い

プルリクエストの取り扱いについては、[プルリクエストとレビュー](/pages/project-management/development-rules/pull-request-review)をご参照ください。

### 定期的な更新と報告

1. **デイリースタンドアップ**: TeamStatusを使用して、毎日更新を提供します。
   - 各チームメンバーは、昨日行ったこと、今日行うこと、直面しているブロッカーについてのステータスをログに記録します。
2. **週次同期**: 毎週チームミーティングを行い、進捗をレビューし、重要な問題を議論し、優先順位を再調整します。
   - GitHub Issuesをレビューします。
   - 締め切り日と今後の期限を分析します。
   - 重要な成果を強調し、ブロッカーや遅延に対処します。

## ベストプラクティス

- **透明性**: すべてのチームメンバーがGitHub Issuesにアクセスでき、ステータスを確認できるようにして、透明性を維持します。
- **コミュニケーションの優先**: 定期的な更新とオープンなコミュニケーションは、問題を迅速に解決し、全員を調整するのに役立ちます。
- **整理整頓**: ラベルと締め切りを効果的に使用して、タスクを整理し、優先順位を付けます。
- **一貫した更新**: GitHub IssuesとTeamStatusが常に最新の状態を反映するように更新します。
- **厳格なレビュー過程**: PRは少なくとも2人のチームメンバーによって徹底的にレビューされ、コード品質を維持し、知識共有を促進します。
- **一貫した命名規則**: PRの命名規則（`feature/frontend_<developer-name>_<feature-name>_<issue-number>`）に従い、整合性を保ち、作業の追跡を容易にします。
