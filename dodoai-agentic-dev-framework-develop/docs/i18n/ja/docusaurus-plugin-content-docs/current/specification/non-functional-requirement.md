## 概要
非機能要件(NFR)は、ソフトウェアシステムの品質属性を指定し、システムのパフォーマンス、セキュリティ、使いやすさの基準を定義します。これにより、ユーザーの満足度に寄与します。

## 目標：
- システムの動作に関する明確な基準を提供する。
- パフォーマンス、セキュリティ、使いやすさのベンチマークを確立する。
- システム属性がユーザーおよびビジネスのニーズに一致していることを確認する。

## 重要な側面
- 応答時間や負荷容量などのパフォーマンス指標。
- データ保護およびユーザープライバシーのためのセキュリティプロトコル。
- インターフェース設計およびアクセシビリティのための使いやすさ基準。
- 一貫したシステムの可用性のための信頼性プロトコル。
- システムの更新およびドキュメント作成に関するメンテナンスガイドライン。
- 法的および規制基準の遵守。

### 非機能要件タスクのためのSSツールの使用方法：
SSツールを使用して、ビジネス要件を非機能要件(NFR)に変換する手順は次の通りです：

1. パフォーマンス基準を入力し、応答時間およびシステムの可用性を定義します。
2. セキュリティ対策を指定し、データの暗号化およびコンプライアンスを含めます。
3. ユーザビリティ機能を詳細に説明し、ユーザーインターフェース設計およびアクセシビリティ基準を示します。

## 出力例：
**以下の例は参考用として提供されています。特定のプロジェクト要件に合わせてカスタマイズする必要があります。**

```
### パフォーマンス
- システムは、標準操作中にLLMスイッチを2秒以内で実行できるようにする必要があります。

### セキュリティ
- データは、AES-256標準を使用して転送中および保存中に暗号化されるべきです。
- LLMスイッチに関連するすべてのアクションについて、包括的な監査ログを保持します。

### ユーザビリティ
- ユーザーインターフェースの設計は、アクセシビリティのためにWCAG 2.1 AA基準に準拠する必要があります。
```
