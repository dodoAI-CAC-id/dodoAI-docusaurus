# デザインシステムの概要と目的

## 概要

dodoAI デザインシステムは、フロントエンド開発における「車輪の再発明」を防ぎ、標準化された共通コンポーネントを一貫して使用することを目的としています。これにより、無駄な開発コストや技術的負債を削減し、製品の品質とブランドの一貫性を向上させます。

## 目的

- **一貫性の確保**: すべての製品やプラットフォームで、統一されたデザインとユーザー体験を実現する。
- **効率的な開発**: 標準化されたコンポーネントを再利用することで生産性を向上させ、開発時間を短縮する。
- **技術的負債の削減**: 統一された開発基盤により、将来の保守コストや技術的負担を軽減する。

# 想定利用者

dodoAI デザインシステムは次の利用者を対象としています：

- **デザイナー**
- **開発者（主にフロントエンドエンジニア）**
- **サービスプランナーおよび情報アーキテクト**

# 使用方法

dodoAI デザインシステムは以下の3つの主要要素で構成されています：

[https://www.figma.com/design/8JwpYsftZbjYfJDKxSm5IZ/dodoAI-Design-System?node-id=753-2670&node-type=canvas&t=QT5ixNjWWNw3tGPG-0](https://www.figma.com/design/8JwpYsftZbjYfJDKxSm5IZ/dodoAI-Design-System?node-id=753-2670&node-type=canvas&t=QT5ixNjWWNw3tGPG-0)

### 1. 使用ガイド

- デザインシステムの使い方と運用方法の概要が提供されています。

### 2. コンポーネントデザイン

- **既存コンポーネントの使用**: フロントエンド開発において、一貫したデザインと機能を確保するために、このデザインドキュメントで定義されたUIコンポーネントのいずれかを使用することが不可欠です。

- **Widgetbookからのソースコード使用**: 開発者が使用するUIコンポーネントのソースコードは常にWidgetbookから取得し、スタイルガイドが適用された信頼性のあるソースコードを提供します。

- **新しいUIコンポーネントの追加**:
    1. **デザインドキュメントに追加**: まず、新しいデザインをこのドキュメントに追加します。
    2. **Figma to Codeを使ってコード化**: Figma to Codeを使用してソースコードをエクスポートします。
    3. **Widgetbookで定義**: エクスポートされたソースコードをWidgetbookで定義し、他の開発者が利用できるようにします。

### 3. スタイルガイド

- **スタイルの遵守**: dodoAI製品の品質とブランドを一貫して維持するために、このガイドで定義されたスタイル（カラー、タイポグラフィ、アイコン、レイアウトなど）に従ってください。

- **新しいデザインのガイドライン**: 新しいデザインを追加する際は、常にこのスタイルガイドに従い、新しいコンポーネントやページにおいてブランドの一貫性を確保してください。

- **開発者の役割**: フロントエンド開発者は通常、Widgetbookのコンポーネントを使用することでこのスタイルガイドを間接的に参照します。開発者は独自のUIを実装せず、新しいコンポーネントが必要な場合はデザインの作成をデザイナーに依頼してください。

### 4. アセットライブラリ

- **適切な使用方法**: ロゴを使用する際は、常にこのアセットライブラリから適切なサイズとフォーマットでエクスポートしてください。不適切な使用は、製品の品質やブランドイメージに大きく影響する可能性があります。

- **厳格な遵守**: ロゴやブランドアセットを扱う際のルールを理解し、色や比率の変更を禁止するなどの規定を遵守してください。

### 想定利用者による使用法

想定される利用者とそれぞれの役割に基づいて、dodoAI デザインシステムの使用は異なる場合があります。基本的な使用方法は以下のとおりです：

| **想定利用者**                        | **使用法**                                                                                                                                                                                                                          |
|------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **デザイナー**                             | <ul><li>デザイナーはデザインシステムからコンポーネントを選択して編集し、各パーツをゼロから作成することなく画面デザインを効率化できます。</li><li>パーツの作成ではなく、画面デザインの計画により多くのリソースを割り当てることができます。</li><li>アクセシビリティガイドラインが含まれており、デザイン作業中にすばやく参照できます。</li></ul> |
| **開発者**                            | <ul><li>スクリーンやスクリーン遷移をプログラミングする際、コンポーネント仕様が明確であれば、コードを書くのが容易になります。</li><li>テンプレートが提供されている場合、それらを予めコード化することで、後続の作業の効率を向上させます。</li><li>コードスニペットがあることで、開発者はコンポーネントコードをゼロから作成することなく、事前に書かれたコードを編集できます。</li><li>開発中にすぐ参照できるアクセシビリティガイドラインが含まれています。</li></ul> |
| **ウェブサイトプランナー/情報アーキテクト** | <ul><li>デザインシステムのコンポーネントは、画面イメージ作成時に使用できます。</li><li>テンプレートを使用することで、画面イメージをゼロから作成する必要がなくなります。</li><li>アクセシビリティガイドラインがあり、プランナーが計画段階からアクセシビリティを考慮できます。</li></ul> |
| **調達仕様プランナー**     | <ul><li>設計要件または受け入れ基準としてデザインシステムを設定することで、契約業者へのガバナンスを維持できます。</li><li>デザインシステムには多くのアクセシビリティ考慮が含まれており、アクセシビリティ遵守を確実にするのに役立ちます。</li></ul> |

# デザインシステム運用ガイドライン

- **一貫性の維持**: スタイルガイドに従い、可能な限り既存のコンポーネントやスタイルを使用して設計と開発の一貫性を維持します。
- **コミュニケーション**: デザイナーと開発者の間で密なコミュニケーションを行い、要件や更新を明確に共有してください。
- **Widgetbookの更新**: デザインシステムが更新された際は、Widgetbookも常に最新の状態に保つようにしてください。

### 開発者ノート

- **カスタム実装を避ける**: フロントエンド開発者は独自にUIを実装しないでください。既存のコンポーネントがない場合は、デザイナーに新しいデザインを依頼してください。
- **デザインの一貫性を維持する**: 開発者はWidgetbookのコンポーネントを直接使用し、デザインとの一貫性を保ちます。
- **追加コンポーネントの追加手順**:

  - 必要性の確認: 木戸さん、市川さん
  - 承認: 村上さん
  - 市川さんが設計者にタスクを割り当てて見積もりと作業依頼
  - デザインが完了したら、デザインシステムに追加
  - Widgetbookの開発者用に新しいコンポーネントのイシューを作成
  - デザインシステムに基づきWidgetbookで新しいコンポーネントを反映
  - Widgetbookで新しいコンポーネントを利用するためのイシューを開発者に作成
