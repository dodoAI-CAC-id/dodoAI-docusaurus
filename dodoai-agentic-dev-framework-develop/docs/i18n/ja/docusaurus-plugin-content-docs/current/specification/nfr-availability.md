# 定義ガイド – 可用性非機能要件

- このガイドを使用して、システムの可用性要件を包括的に定義します。
- サンプル値をそのままコピーしないでください。ビジネスニーズ、システム特性、ライフサイクル、現実的な成長に基づいてカスタマイズしてください。
- どの要件が重要かを明確に示し、根拠、メトリクス、制約、将来性を考慮した検討事項を提供してください。

## 1. 可用性目標

### 1.1 システム稼働時間
- **稼働時間目標:** システム全体の可用性目標を定義（例：99.9%、99.95%、99.99%）
- **測定期間:** 可用性を測定する期間（月次、年次、四半期）
- **ダウンタイム許容度:** 許容される計画外停止時間（例：月間43分、年間8.76時間）

### 1.2 サービスレベル目標（SLO）
- **応答時間SLO:** 正常な応答時間の目標（例：95%のリクエストが200ms以内）
- **エラー率SLO:** 許容されるエラー率（例：0.1%未満）
- **スループットSLO:** 最小処理能力の保証

### 1.3 計画メンテナンス
- **メンテナンス窓:** 定期メンテナンスの許可時間帯
- **メンテナンス頻度:** 計画メンテナンスの実施頻度
- **影響範囲:** メンテナンス中のサービス影響度

## 2. 障害回復要件

### 2.1 復旧時間目標（RTO）
- **システム全体RTO:** システム全体の復旧時間目標
- **重要サービスRTO:** ビジネスクリティカルなサービスの復旧時間
- **段階的復旧:** 部分的な機能復旧の時間目標

### 2.2 復旧ポイント目標（RPO）
- **データ損失許容度:** 許容されるデータ損失の時間範囲
- **バックアップ頻度:** データバックアップの実施頻度
- **レプリケーション要件:** リアルタイムデータ複製の要件

### 2.3 障害検知時間
- **検知時間目標:** 障害発生から検知までの時間
- **アラート応答時間:** アラート発生から対応開始までの時間
- **エスカレーション時間:** 問題エスカレーションの時間枠

## 3. 冗長性とフェイルオーバー

### 3.1 システム冗長性
- **単一障害点の排除:** 重要コンポーネントの冗長化
- **地理的分散:** データセンター間での分散配置
- **負荷分散:** トラフィック分散とフェイルオーバー機能

### 3.2 自動フェイルオーバー
- **フェイルオーバー時間:** 自動切り替えの実行時間
- **フェイルバック手順:** 正常状態への復帰プロセス
- **データ整合性:** フェイルオーバー時のデータ一貫性保証

### 3.3 災害復旧
- **災害復旧サイト:** 代替サイトの準備と維持
- **復旧手順:** 災害時の復旧プロセス
- **復旧テスト:** 定期的な災害復旧テストの実施

## 4. 監視と測定

### 4.1 可用性監視
- **監視項目:** システム稼働状況の監視対象
- **監視頻度:** 監視チェックの実行間隔
- **監視範囲:** 内部監視と外部監視の範囲

### 4.2 パフォーマンス監視
- **応答時間監視:** リアルタイムの応答時間測定
- **リソース監視:** CPU、メモリ、ディスク使用率の監視
- **容量監視:** システム容量と使用率の追跡

### 4.3 アラートとエスカレーション
- **アラート閾値:** 各メトリクスのアラート基準
- **通知方法:** アラート通知の手段と対象者
- **エスカレーション手順:** 問題の段階的エスカレーション

## 5. 可用性テスト

### 5.1 障害テスト
- **障害シミュレーション:** 計画的な障害テストの実施
- **カオスエンジニアリング:** システム耐性の検証
- **負荷テスト:** 高負荷時の可用性検証

### 5.2 復旧テスト
- **復旧手順テスト:** 復旧プロセスの定期的な検証
- **バックアップテスト:** バックアップからの復元テスト
- **災害復旧演習:** 全社的な災害復旧訓練

---

**目的**

可用性要件を明確に定義することで、システムが期待される稼働率を維持し、ビジネス継続性を確保します。これらの要件は、インフラ設計、運用プロセス、監視戦略の基盤となります。
