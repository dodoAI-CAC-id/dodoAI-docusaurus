# 移植性と移行 – 定義ガイド

- このガイドを使用して、システムの移植性と移行要件を包括的に定義します。
- そのままコピーしないでください。常に実際のビジネス、技術、組織コンテキストに要件を適応させてください。
- 各要件について、目標レベル、根拠、メトリクス（該当する場合）、依存関係やリスクを指定してください。

## 1. 移行期間とスケジューリング

### 1.1 移行期間
- **定義すべき内容:** 移行プロセスの予定期間を指定—初期計画から完全カットオーバー/本番まで、許可されるシステムダウンタイム、並行運用の可能性、バックアップ/待機期間、例外時のロールバック時間枠を含む
- **例:** 「移行不要」「3ヶ月未満」「6ヶ月未満」「1年未満」「2年未満」または「2年以上」

### 1.2 移行のための許可ダウンタイム
- **定義すべき内容:** 移行カットオーバー中の最大許可ダウンタイム（例：いつでも許可、指定日のみ、5日未満、1日未満、夜間のみ、またはまったく許可しない）
- **注意:** より制限的な時間枠には、より多くの自動化と準備が必要

### 1.3 並行運用
- **定義すべき内容:** 移行計画の一部として、旧システムと新システムが並行して稼働するかどうか（どの程度の期間）
- **オプション:** 「不要」（ビッグバンカットオーバー）、「並行運用必要」（段階的アプローチ）

## 2. 移行アプローチ

### 2.1 システム展開ステップ（場所）
- **定義すべき内容:** 移行/新規展開が一度に行われるか、サイト/オフィスごとに複数の段階/ステップで行われるか
- **例:** 「単一サイト、段階なし」「ビッグバン展開」「5ステップ未満の段階的展開」「10段階以上」など

### 2.2 ビジネス展開ステップ（機能/プロセス）
- **定義すべき内容:** ビジネス側の移行がすべて一度にカットオーバーされるか、いくつかの定義された段階で行われるか
- **例:** 「すべてのビジネスを一度に」「4ステップ未満」「6ステップ未満」「10ステップ未満」「10ステップ以上」

## 3. 移行対象

### 3.1 機器/システム
- **定義すべき内容:** 置き換えの範囲—変更なし、ハードウェアのみ、ハードウェア + OS/ミドルウェア、または統合を含むすべてのシステムコンポーネント
- **例:** 「機器置き換えなし」「ハードウェアのみ」「ハードウェアとOS」「フルシステム」または「統合を含むフルシステム」

### 3.2 データ量と形式
- **定義すべき内容:** 移行が必要な総データ（プログラムを含む）、およびソースとターゲット間で形式が一致するかどうか
- **例:** 「データ移行なし」「1テラバイト未満」「1ペタバイト未満」「1ペタバイト以上」など。形式変換が必要かどうかを指定

### 3.3 移行メディア量とタイプ
- **定義すべき内容:** 移行に使用される物理または論理メディアの数とタイプ
- **例:** 「移行メディアなし」「10テープ未満（1テラバイト未満）」「1000テープ未満（1ペタバイト未満）」「1000テープ以上」など。また、メディアタイプの数も定義：単一、デュアル、トリプル、4タイプ、5タイプ以上

### 3.4 変換範囲とツール複雑性
- **定義すべき内容:** 変換/コンバージョンが必要なデータ量、および移行/変換ツールの複雑性（例：変換ルール数）
- **例:** 「変換なし」「1テラバイト未満」「1ペタバイト未満」「1ペタバイト以上」など。複雑性：「ツール不要/既存ツールで十分」「10ルール未満」「50ルール未満」「100ルール未満」「100ルール以上」

## 4. 移行計画

### 4.1 移行タスク割り当て
- **定義すべき内容:** 移行タスクを誰が実行するか（ユーザー、ベンダー、または共同）
- **オプション:** 「すべてのタスクをユーザーが実行」「協力/共有タスク」「すべてのタスクをベンダーが実行」

### 4.2 リハーサルとドライラン
- **定義すべき内容:** 移行リハーサルが実行されるかどうかとその方法（予想シナリオと例外処理について）、どのようなリハーサル環境が使用されるか（実際の本番データかどうか）、リハーサル回数
- **例:** リハーサルなし、通常シナリオのみ、通常とロールバック両方、システム障害復旧を完全に含む。リハーサル環境：「なし」「本番データ許可」「本番データ不許可」。回数：なし、1回、2回、3回、4回、5回以上

### 4.3 外部統合のリハーサル
- **定義すべき内容:** 外部接続/統合が移行リハーサルに含まれるかどうか、インターフェース変更の有無
- **オプション:** なし、仕様変更なしで含む、仕様変更ありで含む

### 4.4 トラブルシューティング計画
- **定義すべき内容:** 移行中の問題に対応するための文書化された計画があるか—誰が対応するかだけでなく、エスカレーション、ロールバック、サポート連絡先、対策を含む
- **オプション:** 計画なし；対応構造定義済み；対応構造 + 具体的手順定義済み

---

## ドキュメントガイドライン

- すべての移行と移植性の側面について、範囲、スケジュール/制約、責任者、緊急時対策を明確に指定してください
- リスク、ロールバック計画、ビジネス–リスク/コスト トレードオフを含む、各移行アプローチの根拠を記載してください
- 可能な限り測定可能な目標を提供してください（例：最大ダウンタイム、量、ステップ数、保持期間）
- システム規模、ビジネス重要性、変更リスクに応じて要件を調整してください

---

**目的**

このガイドラインは、大小のシステムプロジェクトに適用できる、徹底的でリスクベース、実用的な方法で、すべての関連する移行と移植性要件を文書化するのに役立ちます。
